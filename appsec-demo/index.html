Application Security Review: proof of concept

Three demo applications taken through an AppSec review: a filled-out intake form, an automated pipeline run, and a full review report with a decision. One is blocked, one is approved with a condition, one is clean.

Everything here is fictional. Acme Corp, the people, the tickets and the findings are invented. The code, the scanner output and the code excerpts in the PDFs are real and come from the demo apps in this repository. The payments and leave apps are deliberately vulnerable: run them on localhost only.

Demo AppSec pipeline

Nine stages (inventory, secret scan, SAST, dependency scan, IaC scan, container scan, SBOM, DAST, release gate) that really run against each app and enforce a policy. The viewer replays a recorded run; the GitHub Actions workflow runs it on every push.

Suggested five-minute walkthrough

  1. Start at the portfolio summary PDF. Three apps, three outcomes, and the point that scanners miss access-control and design flaws.
  2. Open the intake form for Payments Portal. This is what a team submits; the AppSec tier decides review depth.
  3. Open the pipeline viewer, pick Payments Portal and press Replay. The gate blocks the release with the reasons shown.
  4. Open the Payments review PDF. Each finding has a CVSS score, CWE/OWASP mapping, a real code excerpt and a fix. Compare to the pipeline's output.
  5. Switch to Leave Tracker. The gate passes but the review finds an IDOR the tools cannot see (LV-01). That is the case for a manual review.
  6. Finish on Inventory API. A clean pass: the reference for what good looks like.
